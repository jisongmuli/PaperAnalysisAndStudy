# 论文解析与提问 · PaperInsight

在自己的电脑上阅读论文：左侧保留原文，右侧为每个段落提供独立提问入口。回答默认结合全文，支持继续追问、点击引用定位和导出阅读笔记。

![逐段阅读与原 PDF 公式核对](docs/screenshots/reader-preview.png)

## 使用方式

1. 上传 Word（`.docx`）、PDF、TXT / Markdown，或直接粘贴文本；单文件最大 60 MB。
2. 通过目录、搜索或段落编号定位原文，在对应段落右侧提问。
3. 继续追问同一段；点击回答里的 `[第N段]` 回到参考原文。需要比较多个段落时使用「跨段落提问」。
4. 用「导出」保存 Markdown、JSON、Word 或浏览器打印的 PDF 阅读笔记。

## 本次改进

- 新的中文阅读首页、文档导航、原文搜索、已提问筛选和快捷问题。
- 原文与问题逐段对应；流式回答变长时保持行高一致。左右滚动、引用定位和长文档跳转保持同步。
- 默认结合全文回答，带上当前段落及同一段的成功对话记录。超出预算时保留当前段落，并按问题相关性选取证据；界面标明是否节选。
- 回答显示本次实际参考的段落数；引用只对本次提供的有效段落开放定位。
- PDF 改进双栏阅读顺序、标题和目录识别、行内引用、混合字体表格的行列重建，减少正文误拆和中文被误判为分式的问题。
- PDF 公式优先显示原 PDF 截图，可放大、打开原页或查看提取的公式文本；表格也有原页对照。当前模型支持图片时，提问可同时参考已加载的公式截图。
- 「重新解析（保留旧版）」生成一个新文档，保留旧文档、原文件与旧问答。
- 草稿按文档和段落保存，刷新后恢复；问答自动保存。中文输入法回车不误发，失败可重试，生成可停止。
- 修复修改设置时意外清空已存密钥、文档标题未保存、异常断流被当成成功、切换文档时旧请求覆盖新文档的问题。
- 论文内容作为参考材料，不具有系统指令或用户请求的权限。

## 在本机运行

推荐 Node.js 24。首次安装需要网络下载依赖。

```sh
git clone https://github.com/jisongmuli/PaperAnalysisAndStudy.git
cd PaperAnalysisAndStudy
npm install
npm start
```

打开 <http://127.0.0.1:8787/>。首次在网页「设置」中填写 DeepSeek 密钥并测试连接，之后无需重复输入。安装后也可双击 `启动网站.cmd`；创建桌面快捷方式可运行 `npm run shortcut`。

已有安装更新源码后，先运行 `npm run build`，再重启服务；`npm run serve` 使用已有构建产物启动。开发时运行 `npm run dev`。

也可以复制 `.env.example` 为 `.env`，填写 `DEEPSEEK_API_KEY`。配置优先级为网页设置 > 环境变量 > 默认值。网页保存时密钥输入框留空会保留原密钥。

默认配置：官方 DeepSeek 接口、`deepseek-flash`、全文上下文、56,000 输入预算、4,096 输出上限。输入预算包含系统提示、文档、历史记录与问题，使用估算值；图片另预留预算。兼容接口和模型名称可在设置中修改。

## 数据保存

服务默认只监听 `127.0.0.1`。上传文件、解析结果、问答和密钥配置保存在本机 `data/` 下；备份时关闭服务并复制整个 `data/`。密钥保存在本机配置文件或 `.env` 中，不是浏览器中长期保存的明文凭证。

提问时会向配置的 AI 接口发送选中的论文内容和对话；公式提问可能包含原图截图。可选的「AI 精修解析」也会发送提取文本并产生接口费用。

`.gitignore` 排除密钥、用户上传文件、问答记录、日志和旧截图。仓库仅附带程序生成的公开测试文档与示例界面截图。

## 解析的边界

- 老式 `.doc` 请先用 Word 另存为 `.docx`。
- 扫描件或没有文字层的 PDF 需要先做 OCR，再上传识别后的文件；本版没有内置 OCR。
- PDF 的文字层不包含可靠的公式语义。原图预览可用于核对，提取的 LaTeX、复杂合并单元格、跨页表格和特殊版面仍可能需要人工修正。
- AI 精修针对提取文本，不保证还原原始公式或恢复缺失内容。重要数值、公式和引用应对照原页。
- 这是本机单人使用的应用；多用户登录、共享数据库和公网部署尚未实现。

## 验证

以下测试使用合成样例或隔离的数据目录，不需要真实 API 密钥：

```sh
npm test
npm run test:rich
npm run test:math
npm run test:reader
npm run build
```

`test:reader` 包含全文预算、长文末尾证据、多轮上下文、PDF 双栏/引用/表格、密钥保留、流式异常、原图输入、重解析保留旧问答与笔记导出检查。

另外完成了浏览器检查：文件上传、粘贴入口、草稿刷新恢复、真实 DeepSeek 示例问答与追问、引用定位、复制回答、PDF 公式截图回答、手机布局，以及长论文逐段滚动对齐。真实接口检查使用合成示例，不在仓库中附带用户论文或密钥。

`scripts/` 中其他集成脚本针对运行中的本机服务；其中 `test:live`、`test:ai` 会使用配置的接口并产生费用，应按需手动运行。

## 代码结构

```text
server/                 Express 接口、文档解析、上下文组织、存储与导出
web/src/                React 阅读界面、独立问答框、目录与 PDF 原图预览
scripts/                启动、示例生成和验证脚本
data/samples/           程序生成的 DOCX / PDF 测试样例
.env.example            配置示例，不含真实密钥
启动网站.cmd             Windows 启动入口
```

后端使用 Express，前端使用 React / Vite；PDF 使用 PDF.js，Word 支持表格、图片和 OMML 公式，数学显示使用 KaTeX。
